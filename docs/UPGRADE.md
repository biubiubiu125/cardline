# 本次升级说明

本次修复公开邮箱访问权限、兑换归属与并发占用、管理员会话撤销、状态刷新，以及前端异步请求覆盖问题。首页 `/` 与邮箱取件 `/pickup` 使用同一顶部导航。

## 升级前

1. 备份当前镜像版本、配置文件及 SQLite 数据库。可停服后复制整个数据目录，或使用 SQLite 在线备份；不要在持续写入时只复制主数据库而遗漏 WAL。
2. 生产环境设置独立、随机的 `JWT_SECRET`，至少 32 字符，不得使用旧示例密钥。Compose 要求配置 `ADMIN_PASSWORD`；首次创建管理员时至少 12 字符。已有用户的密码不会因修改环境变量而改变，应从后台修改。
3. 核对历史多账号交付。如果旧版每张卡曾交付多个账号，旧数据库没有记录附加账号归属，无法自动判断哪些未兑换账号实际已售出。根据已有交付文件或业务记录人工核对，将可能重复出售的账号从销售池隔离，再恢复兑换。

## 自动迁移

启动时在事务中初始化表，并按 `SchemaMigration` 记录执行增量迁移：

- 为 `AdminUser` 增加 `sessionVersion`，初始为 `0`。
- 为 `Account` 增加 `redeemedByCard` 及索引；旧记录中已标记 `redeemed` 的账号，按其自身卡密补录归属。
- 未兑换记录不猜测历史交付；历史附加账号需要上述人工核对。

迁移可以重复运行，失败则回滚并阻止服务启动。不要仅用旧版 `CREATE TABLE IF NOT EXISTS` 或 `db:push` 代替本次带数据回填的升级流程。

## 升级后的行为

- 所有升级前的管理员 token 失效，需重新登录。修改密码撤销该管理员所有旧会话，两个改密入口都会返回登录页。
- 每卡数量受后台配置限制，首次兑换在事务中记录全部交付账号，重复兑换只返回同一归属集合。附加账号自己的卡密不可再次领取或读取邮箱。
- 已交付账号禁止重置成未兑换或重新生成卡密。后台物理删除仍会删除账号及邮箱凭据，后续下载无法恢复这些记录。
- 公开邮箱解析、取件和导出需要有效卡密或完整自带凭据；裸邮箱不能查询库内账号。自带凭据不会回写库存状态。
- 取件导出请求从 `keys` 改为 `records`，每条传入 `line` 或有效 `fromCard`，详见 [API 契约](API.md)。前后端需一起更新。
- OpenAI token 正常轮换不会再改变兑换状态；只刷新确认已过期的凭据，不混用微软邮箱 token。

## 本地验证

在 PowerShell 中执行以下命令。联调使用临时 SQLite、脱敏样例及模拟上游，不连接真实邮箱或修改业务数据库。

```powershell
npx prisma generate --schema apps/server/prisma/schema.prisma
npm run build
npm run test:convert
npm run test:security
npm run test:smoke:local
```

浏览器验证可运行 `npm run test:smoke:local -- --serve`，打开输出的本地地址；验证结束在该进程输入 `stop`，关闭服务并清理临时数据库。上述验证不代表真实上游或生产环境已经验证。
